# v0.9.1 Bugfixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the three bugs players report against 0.9.0: hotkeys that ignore a rebind
(#37), the storage chest standing next to the player (#38), and the VR awakening that never
passes its ready check (#36).

**Architecture:** Hotkey registration moves out of the one-shot install functions into
`Bind*` functions that a settings reload can run again over a cleared table. The chest gets
an empty model in the ESP, so wherever its reference ends up there is nothing to see, plus
position logging that decides whether a holding cell is needed later. The readiness check
moves out of `System.cpp` into its own unit that names the condition that failed.

**Tech Stack:** C++23, CommonLibSSE-NG (submodule at `extern/`), `node tools/check.mjs` as
the test harness, `plugin/IsekaiHero.esp` edited at the byte level as Part L of
`docs/CREATION_KIT_ESP.md` was.

**Spec:** [`docs/superpowers/specs/2026-10-30-roadmap-design.md`](../specs/2026-10-30-roadmap-design.md),
section "0.9.1".

## Global Constraints

- **Never bump the mod version.** `CMakeLists.txt` VERSION, `package.ps1`'s default
  `-Version`, git tags and `CHANGELOG.md` headings stay at 0.9.0. New entries go under a
  `## [Unreleased]` heading above `## [0.9.0]`. The first task to write one creates it.
- **Everything committed is in English**: code, comments, commit messages, docs.
- **No committed file may contain the author's real name.** Grep the staged tree
  case-insensitively for the author's first name and surname before every commit, and
  expect no output. Type the names on the command line, never into a file.
- **Commits reference issues with `refs #N`, never `closes #N`.** Issues close after
  in-game verification. GitHub auto-closed #27 and #30 once already.
- **`node tools/check.mjs` passes after every task.** A task adds its check first and
  watches it fail.
- **`build.bat` must compile after every C++ task.** It deploys into the base game's
  `Data\`, which the test setup never reads, so a successful build proves only that the
  code compiles. In-game testing goes through `package.ps1` → `dist\*.7z` → MO2 (Task 5).
- **No co-save change.** Nothing here touches `SaveCallback`/`LoadCallback`, so 0.9.0
  saves load unchanged.
- **Generated files are generated.** If a task adds an `L("…")` string, re-run
  `node tools/extract-strings.mjs` rather than editing `lang/template.txt`. None of the
  tasks below needs one: every new line is a log line.

## Review Focus

1. **A hotkey set to 0 (off) in the MCM.** Expected: the old key stops working on menu
   close. The table is cleared before rebinding, and `Register*` skips 0. Pinned in Task 1.
2. **Opening and closing the journal without changing anything.** Expected: no new log
   line. Every pause menu is the journal, so an unconditional "N hotkeys armed" line would
   flood the log. Pinned in Task 1.
3. **Two settings bound to the same key** (threat-label toggle on the menu key).
   Expected: a warning naming the key, instead of the later binding silently replacing the
   earlier one. Pinned in Task 1.
4. **A 0.9.0 save whose chest reference already exists.** Expected: the chest is invisible
   there too. The model lives on the base record, so an existing reference picks it up on
   its next 3D load. Verified in Task 5.
5. **A readiness check failing on every frame.** Expected: one log line when the blocker
   changes, not one per menu close. Pinned in Task 4.

### Task 1: Rebound hotkeys take hold on menu close (#37)

**Files:**
- Modify: `src/UI/Input.h`, `src/UI/Input.cpp:540-620`
- Modify: `src/Progression.h`, `src/Progression.cpp:841-849` (the hotkey lines inside `Install()`)

- Modify: `src/Config.h:47-48`, `CHANGELOG.md`
- Test: `tools/check.mjs`

**Interfaces:**
- Produces, in `Isekai::UI` (`Input.h`): `void ClearHotkeys();` empties `g_hotkeys` under
  `g_hotkeyMutex`. `g_held` is left alone, because a key held through a rebind is still held.
- Produces: `void Progression::BindHotkeys();`, `void SelfTest::BindHotkeys();`,
  `void UI::BindThreatLabelHotkeys();`. Each registers only from the current `Config`
  values and logs what it bound, as its old install code did. `SelfTest::Install()` and
  `UI::InstallThreatLabels()` contained nothing else, so they are renamed, not kept.
- Produces, in `System.cpp`'s anonymous namespace: `void BindDebugPointsKey();` (renamed
  from `InstallDebugPointsKey`) and `void BindAllHotkeys();`, which calls
  `UI::ClearHotkeys()`, the four `Bind*` functions, then `UI::LogHotkeys()`.

- [ ] **Step 1: Write the failing check** in `tools/check.mjs`:

```js
check("hotkeys: every registration is rebindable, and a settings reload rebinds", () => {
  const sys = read("src/System.cpp");
  const from = sys.indexOf("void ReloadSettings()");
  need(from >= 0, "ReloadSettings not found — parser stale?");
  const reload = sys.slice(from, sys.indexOf("\n        }", from));
  need(reload.includes("BindAllHotkeys();"),
       "ReloadSettings does not call BindAllHotkeys — a rebound key waits for a restart");
  const bindAll = sys.slice(sys.indexOf("void BindAllHotkeys()"));
  need(/ClearHotkeys\(\)/.test(bindAll.slice(0, 800)),
       "BindAllHotkeys does not clear the table first — a key set to 0 would stay armed");

  // Every Register*Hotkey call outside Input.cpp must sit in a function named Bind*.
  const offenders = [];
  for (const f of cppSources().filter((p) => !p.endsWith("UI/Input.cpp"))) {
    const src = read(f);
    for (const m of src.matchAll(/Register(?:Gamepad|VR)?Hotkey\(/g)) {
      const before = src.slice(0, m.index);
      const fn = [...before.matchAll(/\n\s*(?:void|bool)\s+(\w+)\s*\(/g)].pop();
      if (!fn || !fn[1].startsWith("Bind")) offenders.push(`${f} (in ${fn ? fn[1] : "?"})`);
    }
  }
  need(offenders.length === 0, `hotkeys registered outside a Bind* function: ${offenders.join(", ")}`);
  return "reload rebinds, all registrations rebindable";
});
```

`cppSources()` already exists in `check.mjs`. Use it as it is, and adapt the path test to
what it returns.

- [ ] **Step 2: Run it and watch it fail**

Run: `node tools/check.mjs`
Expected: FAIL, "ReloadSettings does not call BindAllHotkeys".

- [ ] **Step 3: Implement the interfaces above.**
  - `ClearHotkeys()` locks `g_hotkeyMutex` and clears the map. There is no swap and no
    second table: every read (`FireHotkey`) and every write already takes that mutex. The
    worst case is a press that arrives between the clear and the rebind, microseconds on
    the main thread, and that press is dropped.
  - In all three `Register*` functions, log a warning before overwriting an existing id:
    `"UI: {} is bound twice — the later binding wins"` with `HotkeyName(id)`.
  - `LogHotkeys()` keeps the last list string in a function-local `static std::string`
    and returns without logging when the new list is identical.
  - In the `kDataLoaded` block, replace the calls to `UI::InstallThreatLabels()`,
    `SelfTest::Install()`, `InstallDebugPointsKey()` and `UI::LogHotkeys()` with one
    `BindAllHotkeys();` at the position of the old `UI::LogHotkeys()`. Remove the hotkey
    lines from `Progression::Install()`. `BindAllHotkeys` replaces them.
  - `ReloadSettings()` calls `BindAllHotkeys()` after `Config::Load()`. Rewrite its comment
    to say that hotkeys rebind there too, and that nothing in `[Hotkey]` needs a restart
    any more.
  - `Config.h:47-48`: replace "Read once at load; the hotkey is registered from it." with
    the fact that it is re-read and rebound whenever the journal (and so the MCM) closes.
  - `CHANGELOG.md` under `## [Unreleased]` → `### Fixed`: a changed hotkey takes effect when
    the MCM closes rather than after a restart. Include the cause in one sentence (`refs #37`).

- [ ] **Step 4: Run the checks and build**

Run: `node tools/check.mjs` → all pass. Run: `build.bat` → builds with no new warnings.

- [ ] **Step 5: Commit**


```cpp
enum class Blocker : std::uint8_t {
    kNone, kNoPlayer, kNo3D, kNoUI, kPaused, kCharGen, kLoading, kNoControlMap, kMovementLocked
};
[[nodiscard]] Blocker          Check();             // pure query, today's IsPlayerReady tests, in order
[[nodiscard]] std::string_view Name(Blocker);       // "no player", "3D not loaded", ... "movement controls locked"
[[nodiscard]] bool             IsPlayerReady();     // Check() == kNone; logs Name() once each time the blocker changes
```

- [ ] **Step 1: Write the failing check**: `"readiness: every blocker has a name, and System.cpp no longer owns the check"`.
  - Parse the `Blocker` enumerators out of `Readiness.h`. Need a `case Blocker::kX:` for
    each in `Readiness.cpp`'s `Name`.
  - Need `System.cpp` to contain neither `bool IsPlayerReady()` nor `g_firstReadyCell`.
  - Need the "not ready yet" log line in `System.cpp` to format `Readiness::Name(`.

- [ ] **Step 2: Run it and watch it fail.** `node tools/check.mjs` → FAIL, `src/Readiness.h`

- [ ] **Step 3: Implement.**

    as today's `IsPlayerReady`, with one return per blocker.
  - `IsPlayerReady()` keeps the last blocker in a `static Blocker` and logs on change:
    `Readiness: not ready — {Name}`, and `Readiness: ready` when the blocker returns to

    `Readiness::Name(Readiness::Check())`.
  - Add both files to `SOURCES` in `CMakeLists.txt`, after `src/System.cpp`.

  **Note:** CommonLibSSE-NG already places `ControlMap`'s runtime data at `0x108` for VR
